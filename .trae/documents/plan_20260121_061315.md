## 问题诊断

1. **Rust 镜像配置错误**: `rsproxy.cn` 镜像返回 404 错误，导致无法下载 `anyhow` 等依赖。
2. **前端依赖缺失**: `Arena.tsx` 中使用了 `@react-three/postprocessing`，但 `package.json` 中并未安装该依赖。
3. **Tauri 版本不匹配**: 前端 `@tauri-apps/api` 版本（^2.1.0）与后端 `tauri` crate 版本（2.0.0）不一致。

## 修复计划

### 1. 修复 Rust 镜像配置

* 在 `src-tauri` 目录下创建 `.cargo/config.toml` 文件。

* 配置稳定的 Rust 镜像源（如中科大 USTC 镜像），替换当前失效的 `rsproxy.cn`。

### 2. 补全前端依赖

* 在 `package.json` 的 `dependencies` 中添加 `@react-three/postprocessing`。

* 运行 `npm install` 安装缺失的包。

### 3. 同步 Tauri 版本

* 更新 `src-tauri/Cargo.toml`，将 `tauri` 和 `tauri-build` 的版本从 `2.0.0` 升级到 `2.1.0`。

* 确保前端 `package.json` 中的 `@tauri-apps/api` 和 `@tauri-apps/cli` 也处于 `^2.1.0`。

### 4. 验证修复

* 重新运行 `npm run tauri dev`，观察是否能正常编译前端并启动 Rust 后端。

## 预期结果

* Rust 依赖将通过新的镜像源成功下载。

* Vite 将能够正确解析 `@react-three/postprocessing`。

* Tauri 的版本匹配检查将通过。
