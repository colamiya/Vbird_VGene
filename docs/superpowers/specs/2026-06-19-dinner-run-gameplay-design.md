# V-GENE 下饭局玩法设计

## 背景

用户确认游戏的基础需求是“下饭”：玩家在吃饭前点开游戏开始一局，然后观看数字生命演化、互相进化、帮助、攻击、随机事件与历史形成。玩法需要兼顾科学性、历史性、随机性、可商业化和低操作负担。

当前代码已有 Tauri/React/Rust 仿真骨架：

- `src/App.tsx` 负责阶段流转、运行状态、世界轮询、实体选择和基础干预。
- `src/components/Arena.tsx` 负责 3D 实体群观看和点击干预。
- `src-tauri/src/evolution/simulation_engine.rs` 负责实体执行、能量、毒素、碰撞、捕食者、选择和突变。
- `src-tauri/src/world_commands.rs` 暴露世界二进制、实体详情、谱系、英灵殿和 `interfere_at`。

缺口不是仿真是否存在，而是“玩家为什么继续看、每局发生了什么、什么时候算一局结束、如何轻操作、如何复盘传播”。

## 目标

1. 支持玩家选择局长：短局、中局、长局都要。
2. 支持玩家选择加速倍率：观看速度交给玩家控制。
3. 形成 8-12 分钟可消费的默认下饭体验，同时保留 15-20 分钟和 30 分钟以上的沙盒体验。
4. 局内持续生成历史事件，不做纯 UI 假播报，事件必须由世界数据或玩家行为触发。
5. 玩家操作保持轻量：可以帮助、攻击、隔离、观察，但不要求高频微操。
6. 复盘产出可收藏、可分享、可商业化的“文明史卡片”和“英灵 DNA”。

## 非目标

- 不在第一版加入完整经济系统、付费数值、联网赛季或账号系统。
- 不改变 Wasm DNA 的核心安全约束。
- 不把所有事件都做成后端强一致持久化。第一版允许局内事件在前端会话层聚合，但事件来源必须来自真实仿真指标、实体数据或已执行的玩家干预。
- 不把“加速”实现为简单 UI 假时间。加速应最终影响仿真节奏或采样节奏；第一版可以先通过运行节流配置和前端事件采样频率实现。

## 核心体验

默认入口从“启动创世”升级为“开始一局”。玩家先选择：

- 局长：`快餐局 8-12 分钟`、`正餐局 15-20 分钟`、`长桌局 30 分钟以上`。
- 加速：`1x`、`2x`、`4x`、`8x`。
- 主题：可复用现有环境与胜出规则，例如大地、深海、深空，生存、掠夺、极简。

进入局内后，玩家主要观看数字生命自动演化。系统根据真实世界状态生成历史事件，例如：

- 首个高分个体出现。
- 某个谱系连续进化。
- 合作群体形成。
- 捕食者入侵。
- 大量实体能量归零。
- 熵值快速上升。
- 英灵入殿。
- 玩家干预改变局部局势。

玩家每隔一段时间可以使用轻干预。干预不是复杂技能树，而是 1 次点击即可理解：

- `祝福`：提升区域内实体能量和短期生存率。
- `投毒`：提升区域毒素或压力，测试鲁棒性。
- `隔离`：临时保护一个实体或小区域，降低碰撞/攻击风险。
- `放逐`：削弱或推离强攻击实体。
- `钉选观察`：锁定一个实体/谱系，事件流优先讲述它的历史。

局结束时生成复盘：

- 本局时间、加速倍率、主题。
- 文明阶段时间线。
- 关键事件列表。
- 最强英灵与 DNA 摘要。
- 灭绝/胜出原因。
- 玩家干预次数与影响。
- 可分享的战报文案。

## 局长与加速

### 局长档位

`MealRunLength`：

- `Snack`：目标 8-12 分钟，默认值，事件密度高，适合随手开。
- `Dinner`：目标 15-20 分钟，事件节奏更舒展，适合完整观看。
- `LongTable`：目标 30 分钟以上，偏沙盒和挂机。

每个档位定义：

- `targetMinutes`：目标真实时间。
- `phasePlan`：五段阶段比例。
- `eventDensity`：每分钟期望事件数。
- `interventionCooldown`：干预冷却。
- `autoReview`：到时是否自动进入复盘。

### 加速倍率

`RunSpeed`：

- `1x`：正常观看。
- `2x`：轻快观看。
- `4x`：快速形成历史。
- `8x`：观察实验或长局快进。

第一版实现建议：

- 前端把局长和倍率转成运行设置。
- 后端通过 `evolutionThrottle` 调整仿真循环间隔。
- 前端事件采样按倍率调整，但事件显示不能刷屏，需要节流和合并。
- `8x` 下 UI 仍保持低频播报，避免事件流不可读。

## 局内阶段

统一采用五段历史结构，不同局长只改变持续时间和事件密度：

1. `创世期`：初代 DNA、环境、任务目标、初始种群。
2. `爆发期`：突变频繁，快速产生分支。
3. `分化期`：合作、掠食、极简、高效率等流派开始出现。
4. `危机期`：熵升高、捕食者、大量死亡、毒素积累。
5. `封神期`：强者入殿，谱系定型，进入复盘。

阶段由 `RunSession` 根据真实时间、倍率和世界指标共同判断。不能只靠固定计时；例如熵值或死亡率过高时，可以提前触发危机期。

## 数据模型

前端新增共享类型，建议放在 `src/types/world.ts` 或独立 `src/types/runSession.ts`：

- `MealRunLength`
- `RunSpeed`
- `RunPhase`
- `WorldEvent`
- `PlayerIntervention`
- `RunSession`
- `RunSummary`

后端第一版可以先新增 command：

- `apply_player_intervention(kind, x, y, z, entity_id?)`
- `get_run_story_snapshot()` 可选，若第一版事件先在前端聚合，则该 command 延后。

`WorldEvent` 字段：

- `id`
- `time`
- `phase`
- `kind`
- `severity`
- `title`
- `body`
- `entityId`
- `metric`

## 架构

### 前端

新增模块：

- `src/utils/runSession.ts`：局长、阶段、倍率、倒计时、事件采样。
- `src/utils/worldEvents.ts`：从 `WorldStats`、`EntityView[]`、`Entity`、玩家操作中推导历史事件。
- `src/components/RunSetupPanel.tsx`：局长和加速选择。
- `src/components/NarrativeFeed.tsx`：局内历史事件流。
- `src/components/InterventionDock.tsx`：祝福、投毒、隔离、放逐、钉选观察。
- `src/components/RunChronicle.tsx`：复盘故事卡，可先并入 `PhoenixReview`。

调整模块：

- `MotherMachine.tsx`：保留高级配置，但加入局长/加速的更直观入口。
- `App.tsx`：持有 `RunSession` 和事件列表，但不要继续无限膨胀；事件生成逻辑下沉到 utils。
- `Arena.tsx`：支持当前干预模式。点击世界坐标时调用对应干预，而不是只有统一 `interfere_at`。
- `PhoenixReview.tsx`：展示局内事件时间线和分享文案。

### 后端

新增或调整：

- 在 `world_commands.rs` 中把 `interfere_at` 扩展成更通用的干预 command，旧 command 可保留兼容。
- 在 `simulation_engine.rs` 中让干预影响实体能量、毒素、攻击/防御或位置，但必须有限制，避免玩家一键摧毁整个世界。
- 长期应增加 `run_commands.rs` 或 `session_commands.rs`，不要把会话逻辑继续堆回 `main.rs`。

## 事件生成规则

第一版事件必须可解释、可节流、可复盘。

示例规则：

- `FIRST_APEX`：首次出现 `score >= 80` 的实体。
- `LINEAGE_RISE`：同一父系连续出现高分后代。
- `MASS_EXTINCTION`：种群在短窗口内下降超过阈值。
- `TOXIN_CRISIS`：平均毒素超过阈值。
- `COOPERATION_CLUSTER`：高 altruism 和 high collaboration 实体占比上升。
- `PREDATOR_RAID`：高 attack/低 altruism 实体出现并造成死亡。
- `PLAYER_BLESSING`：玩家祝福影响实体数大于 0。
- `PLAYER_POISON`：玩家投毒影响实体数大于 0。
- `HALL_OF_FAME`：英灵殿新增实体。

事件流最多保留最近 100 条，复盘保留关键 20-30 条，避免长局内存增长。

## 商业化设计

第一版商业化只做可扩展接口，不接支付：

- `文明史卡片`：每局复盘可生成一段战报。
- `物种馆`：收藏英灵 DNA 和代表事件。
- `视觉主题`：未来可卖星域皮肤、粒子外观、事件播报风格。
- `赛季悬赏`：未来把 `sort_i32`、`rle` 等 useful-work 任务包装成赛季任务。

禁止第一版引入数值付费。商业化优先走外观、收藏、复盘传播和挑战赛。

## 错误处理

- 干预 command 失败时显示在局内状态区，并播放错误音效。
- 加速倍率过高导致世界读取失败时，自动降回较低采样频率并提示。
- 局结束时若后端停止失败，仍可进入复盘，但复盘标记为“后端停止异常，统计可能不完整”。
- 事件生成不得抛异常中断世界轮询。

## 测试与验证计划

按用户要求，本阶段不运行测试、不做冒烟、不启动应用。实现完成后统一验证：

- `npm run build`
- `cd src-tauri; cargo check`
- `.\run.ps1 -Action Check`
- Tauri 手动验证：局长选择、加速倍率、干预、事件流、自动复盘、暂停/恢复、窗口关闭。
